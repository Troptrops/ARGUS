# Publish ARGUS on GitHub — browser instructions

1. Sign in as `Troptrops` and visit https://github.com/new .
2. Owner: `Troptrops`; name: `argus-surface-support`; visibility: **Public**.
3. Description: `Auditable prediction-to-CT storage checks for Vesuvius Challenge scroll data.`
4. **Do not** precreate README, license, or .gitignore, because this folder already includes them.
5. Click **Create repository**.
6. On the resulting empty-repository page, select **uploading an existing file** (or **Add file > Upload files**).
7. Upload the contents of this extracted folder (README.md, LICENSE, argus_support/, docs/, evidence/, protocol/, submission/, tests/, tools/, etc.), preserving folders. Do **not** upload the enclosing directory as a nested folder. If GitHub fails to preserve hidden `.github` or `.gitignore`, add those separately later.
8. Commit with message `Initial ARGUS v0.4.2 public research release`.
9. Confirm README is rendered on the repo front page and that `LICENSE`, `pyproject.toml` and `argus_support` are at the repo root.
10. Visit https://github.com/Troptrops/argus-surface-support only after the creation is complete; use the **actual URL** in the Progress Prize form.

Research support: https://drive.google.com/drive/folders/1FDjnVvOUv58AlGtz0MuMRPQUfDbdkbZ1?usp=drive_link . Check Google Drive sharing: General access > Anyone with the link > Viewer. Test in a private/incognito window. Do not make private notes or third-party files public by accident.

Recommended: release verified source and derived summaries on GitHub. Keep large raw captures, experimental archives, 3D models, and underlying scan data in the separately permissioned Drive folder, subject to original licenses. Never upload tokens, private keys, or credentials.
